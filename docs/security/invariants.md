# Security invariants

From spec §45. Each invariant is mapped to the test that enforces it today, or to the phase that will.

| # | Invariant | Enforced by |
|---|---|---|
| 1 | High-risk physical operations go through authenticated, authorized, time-bounded local policy | `//core/policy:policy_test` (deny by default, risk ceilings, human-only security-critical, freshness); `//core/execution:ledger_test` (TTL); `//core/execution:operations_test` (operation catalog: args, target, TTL and window bounds); `EngineTest.LowRiskOperationNameCannotCarryUnlockArgs`, `EngineTest.TtlWindowAndTargetAreBounded`, `HttpE2E.AgentCannotSmuggleUnlockArgsUnderALowRiskOperation`, `HttpE2E.RequestFieldsAreBounded`, `Operations.FreeTextArgsAreBounded`; lowering the arm mode (away → home included) is human-only: `Policy.AgentCannotLowerArmMode`, `EngineTest.AgentCannotLowerArmMode`, `HttpE2E.AgentCannotLowerTheArmMode` |
| 2 | Cloud outage cannot disable local sensing and alarms | Architectural: core and the twin have no network dependency; every scenario runs fully offline |
| 3 | Missing or stale telemetry never reports a sensor healthy or clear | `StateTest.FreshnessNeverReportsUnknownAsFresh`, `StateTest.ReceiptAheadOfTheClockIsStaleNotFresh`; `Policy.SecurityCriticalRequiresFreshTargetState`; `HttpE2E.ReplayedHeartbeatDoesNotKeepADeadDeviceAlive`; a device whose reports are refused or land behind its record is `FAULTED`, not healthy, and a forged boot epoch cannot freeze it (`IngestTest.HugeBootEpochCannotFreezeLaterGenuineBoots`, `EngineTest.SourceResetRecoversAPoisonedDevice`, `HttpE2E.PoisonedBootEpochIsRefusedSurfacedAndRecoverable`); a zone with any stale or silent PIR is never "quiet" (web `zoneActivity` test) |
| 4 | Replayed events and duplicate commands cannot cause repeated physical effects | `IngestTest.DuplicateDeliveryHasNoEffect`, `IngestTest.RefusesSequencesOlderThanWindow`, `Ledger.SameIdempotencyKeyYieldsOneCommand`, `Rules.ReEvaluatingSameEventYieldsSameIntentKey`, `EngineTest.DuplicateMotionDeliveryCausesOneDispatch`, `Ledger.IdempotencyKeysAreScopedToThePrincipal`, `HttpE2E.ReplayedHeartbeatDoesNotKeepADeadDeviceAlive` (replayed CoAP frames refresh no telemetry), `CoapIngress.SpoofedDatagramsCannotPoisonTheRetransmissionCache`, scenario `duplicate_delivery` |
| 5 | Security-critical remote actions expire and need fresh state and authorization | `Ledger.ExpiredCommandIsNeverDispatched`, `Policy.ExpiredRequestDenied`, `Policy.SecurityCriticalRequiresFreshTargetState`; dispatch is the adapter hand-off: `EngineTest.CommandNotHandedOffWithinTtlExpiresAndIsNeverSent`, `HttpE2E.ExpiredCommandIsNeverHandedToTheDevice`; freshness is judged on the target: `EngineTest.CallerExpectCannotMoveTheFreshnessCheckOffTheTarget` |
| 6 | A failed device cannot be misreported as having acted successfully | `Ledger.AckWithoutObservationIsCompletedUnverifiedNeverSuccess`, `Ledger.NoEvidenceInWindowIsUnknownNotSuccess`, `EngineTest.SpeakerSilenceEndsUnknownNotSuccess`; `EngineTest.OnlyTheDerivedObservationVerifiesACommand`, `HttpE2E.CallerCannotChooseWhatIsFreshOrWhatVerifies`, `Ledger.AckOnlyCommandCarryingAnExpectStillNeverVerifies`; only an observation that is current state and newer than the dispatch baseline verifies: `EngineTest.OutOfOrderOlderObservationNeverVerifies`, `EngineTest.ReportNotNewerThanDispatchBaselineNeverVerifies`, `HttpE2E.StaleObservationNeverVerifiesALockCommand`; rule actions are never silently dropped by an id held by another principal: `EngineTest.RuleCommandIdHeldByAnotherPrincipalStillActs`, `HttpE2E.ForeignPrincipalCannotPreclaimRuleCommandIds`, `Ledger.DeniedRequestsDoNotConsumeIdsAndAreBounded`; scenarios `speaker_offline`, `speaker_silent_ack`, `lock_jammed` plus the twin's always-on "verified implies physical effect" invariant; web `outcomeOf` test |
| 7 | Only verified, signed, compatible OTA images are accepted | Hub verifies Ed25519 release signatures from owner keys before offering (`//server:coap_test`); board and revision must match the device (`CoapIngress.CampaignRefusedForAnotherBoardOrRevision`); releases are keyed by board, revision and version, never replaced, and campaigns are pinned to the checked release (`CoapIngress.ImportingAnotherBoardsReleaseCannotChangeAScheduledCampaign`, `FirmwareStore.VersionsParseStrictlyWithoutWrapping`); device checks digest, downgrade, size, power and rolls back (`//firmware/sim:node_test`). On-device signature verification still open (ADR 0014) |
| 8 | Untrusted firmware or module profiles cannot change wiring or current limits by remote manifest | Wiring is a compiled `BoardSupport` table; unknown module codes are never powered; `ConfigUpdate` only tunes bounded behavior (`//firmware/sim:node_test`) |
| 9 | No private credentials or signing keys in the repo, factory logs or client bundle | Configs hold only token hashes; cloud keys come from env vars; `dev_mode` configs, and any config carrying a published dev token hash or device key, refuse non-loopback HTTP and CoAP hosts (`Config.DevModeRefusesNetworkHostsForHttpAndCoap`, `Config.PublishedDevCredentialsAreRefusedOnTheNetworkWithoutDevMode`); token hashes are unique across credentials (`Config.TokenHashesAreUniqueAcrossPrincipalsAndDevices`). Secret scanning still to add |
| 10 | Users and agents act only within authorized property and capability scopes | Device credentials scoped to one device (`HttpE2E` tests); Supabase RLS by property membership;  `Policy.GrantForOtherPropertyDoesNotApply`, `SupabaseAuth.AcceptsMappedValidTokensOnly`, MCP connector tests (no security-critical tools; agent principal), `IngestTest.RejectsForeignPropertyAndUnknownDevice`, `IngestTest.CapabilityMustBeDeclaredAndPayloadMustFitIt`, `IngestTest.EventTypeMustFitPayloadAndFieldsAreBounded`, `HttpE2E.ObservationFieldsAreBoundedAndConsistent`, `ValidateProperty.EmptyCapabilityListDeclaresNone`, `EngineCapabilities.UndeclaredTargetCapabilityIsDenied`, `ValidateProperty.RejectsDeviceFromAnotherProperty`, `ValidateProperty.RejectsAssetAttachingForeignDevice`, `HttpE2E.IdempotencyKeysAndCommandIdsBelongToOnePrincipal` |
| 11 | A hardware safety interlock cannot be overridden by an automation rule | Hardware design (Phase 8). Today rules always act as capped `kRule` principals: `Config.RulePrincipalsAreAlwaysRulesNeverConfiguredIdentities`, `HttpE2E.RulePrincipalCollidingWithAPersonIsRejectedOnPut`, `EngineTest.RuleNamingAHumanPrincipalIsDenied` |
| 12 | Telemetry floods cannot exhaust critical event and control queues | Firmware priority queue drops P3/P2 before P0 (`//firmware/sim:node_test`); per-device CoAP token bucket charged only after HMAC verification and only for fresh frames, with separate per-peer buckets for failed authentication and for replays (`CoapIngress.ForgedFloodCannotThrottleTheGenuineDevice`, `CoapIngress.ReplayedFrameFloodCannotThrottleTheGenuineDevice`); concurrent SSE streams capped, per principal, with owner slots reserved (`HttpE2E.LiveEventStreamsAreCapped`, `HttpE2E.LowPrivilegePrincipalCannotTakeTheOwnersStreams`); command requests rate limited per principal and denials journaled within a budget (`HttpE2E.CommandFloodIsRateLimitedAndDenialsAreBounded`, `EngineTest.UnrecordedDenialLeavesNoTrace`); HTTP request-read deadline and per-peer connection cap (`HttpE2E.SlowlorisConnectionsAreCutAndCapped`); MCP output cannot be broken out of (`connectors/mcp_server` wrapper test); diagnostics bounded and kept out of the journal |
