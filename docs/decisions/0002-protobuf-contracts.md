# ADR 0002: Protobuf as the wire/storage contract, managed with buf

**Status:** Accepted (2026-11-15). Implements spec D15 and §53 WP1.

## Decision
- Canonical schemas live in `contracts/proto/talos/v1/`, package `talos.v1`.
- **buf** enforces `STANDARD` lint rules and `FILE`-level breaking-change detection. CI runs `buf breaking` against `main` on pull requests.
- C++ code is generated by Bazel `cc_proto_library` (`//contracts/proto/talos/v1:talos_cc_proto`). TypeScript code is generated by `protoc-gen-es` (protobuf-es v2) into `web/src/gen/` through `pnpm proto:gen`. The generated TS is gitignored and regenerated in CI.
- Board, module and property configuration is YAML that is an instance of these messages (`contracts/manifests/`). `codec/yaml_loader` converts YAML to protobuf JSON, so there is no second schema language. Unknown keys are errors.
- Timestamps on the wire are `int64 *_unix_ms`, not `google.protobuf.Timestamp`. This keeps the messages friendly to nanopb and embedded encoders later.
- Every new enum has an `*_UNSPECIFIED = 0` value, and the codec treats it as invalid wherever a value is required.

## Compatibility rules
Never renumber or reuse a field. Delete fields only by reserving them. Breaking changes require a new package version (`talos.v2`).
