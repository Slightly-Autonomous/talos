# hardware/results

Machine-generated outputs, regenerated by the scripts in `hardware/scripts/`. Each file states the tool and date that produced it. **These are tool outputs, not proof the design works.**

| File | Produced by | What it shows |
|---|---|---|
| `kicad-check.md` | `check_kicad.py` (kicad-cli 10.0.8) | ERC counts and waivers, netlist round-trip, cross-board connector check, safe defaults, PCB DRC with schematic parity, footprints still to finalise |
| `bom/<board>.csv` | `check_kicad.py` | Grouped BOM from the generator's intended netlist. Footprint "TBD" means it is not drawn yet |
| `pin-to-net/<board>.csv` | `check_kicad.py` | Every pin of every part and its net |
| `schematics/<board>.pdf` | `check_kicad.py --pdf` | Printable schematics for review |
| `power-budget.md` | `power_budget.py` | H2 sleep, peak, charger-thermal and solar model (SRC/EST tagged) |
| `spice.md` | `spice_sim.py` (libngspice, behavioural models) | Slot inrush, radio burst, SW short, I2C rise time, USB priority threshold. CI checks the verdicts |
| `pi.md` | `pi_report.py` (kisi v0.3.3, local) | DC IR drop and current density per rail, steady-state thermal estimate, USB worst case |
| `magnet.md` | `magnet_sim.py` (magpylib, local) | TL-MOD-001 close/open gap for candidate magnets and threshold options |

The fabrication packages live in `hardware/fab/` (made by `export_fab.py`).

Raw kicad-cli ERC reports are not committed, because they embed local absolute paths. Re-run the scripts to reproduce them.
